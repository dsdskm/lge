# Signal Recovery — 상태 표시 모듈 복원 과제

## 배경

오래된 산업 장비를 구동하는 펌웨어 안에는, 장비의 상태를 화면에 글자로
찍어 보여 주는 **상태 표시 모듈**이 들어 있습니다. 이 모듈은 글자 하나하나를
점(`.`)과 선(`-`)으로 이루어진 고유한 **신호 코드**로 표현하도록 만들어졌습니다.

문제는, 이 신호 코드의 대응 규칙을 적어 둔 문서가 소스 코드와 함께
분실되었다는 점입니다. 지금 남아 있는 것은 **컴파일된 실행 파일(`glyphd`)**과
**작동하는 예시 하나**, 그리고 복원해야 할 상태 메시지 목록뿐입니다.

원 개발자는 떠났고, 신호 코드 표는 어디에도 남아 있지 않습니다.
당신의 임무는, 주어진 상태 메시지가 화면에 올바르게 찍히도록
**신호 파일을 직접 복원**하는 것입니다.

> 같은 장비를 오래 다뤄 본 기술자들은 이런 상황을 종종 만납니다. 사양서는
> 사라졌지만 장비는 여전히 돌아갑니다. 장비가 어떻게 반응하는지를 직접
> 관찰해서, 사라진 규칙을 되살리는 수밖에 없습니다.

## 실행 파일

```
./glyphd <신호파일>
```

`glyphd`는 신호 파일을 읽어, 해독한 결과를 **터미널 화면에** 글자 모양으로
그려서 보여 줍니다. 이 모듈은 같은 글자라도 **실행할 때마다 다른 모양과
크기로** 그리도록 설계되어 있습니다 — 글자의 **정체**는 늘 같지만,
**생김새**는 매번 달라집니다.

## 입력 형식

신호 파일은 다음 규칙만 지키면 됩니다.

- 파일은 일반 텍스트입니다.
- **한 줄에 글자 하나**가 대응됩니다.
- 여러 글자를 표현하려면, 글자마다 줄을 나누어(줄바꿈) 차례로 적습니다.
- 각 줄에는 점(`.`)과 선(`-`)만 사용합니다.

예를 들어 세 줄짜리 신호 파일이 올바르게 작성되어 있다면,
화면에는 세 글자가 차례로 그려집니다.

## 작동 예시

함께 제공된 `example_signal.txt` 의 내용은 다음과 같습니다 (한 줄).

```
..-.
```

실행해 보십시오.

```
./glyphd example_signal.txt
```

이 신호 파일을 실행하면, 터미널 화면에 **글자 하나**가 점·선이 아닌
또렷한 글자 모양(ASCII 아트)으로 그려집니다. 어떤 글자가 나타나는지
직접 확인해 보십시오.

이 예시는 다음을 보여 줍니다.

- 신호 파일의 **한 줄**이 **글자 하나**에 대응한다는 점,
- 각 줄이 점(`.`)과 선(`-`)으로 이루어진다는 점,
- 해독에 성공하면 화면에 또렷한 글자 모양이 그려진다는 점.

> 글자의 생김새는 **실행할 때마다 달라집니다.** 같은 신호 파일을 다시
> 실행해도 글자의 모양과 크기는 매번 바뀝니다. 하지만 글자의 정체는
> 늘 같으므로, 어떤 글자인지는 변함없이 알아볼 수 있습니다. 한 글자뿐인
> 이 예시도 실행할 때마다 다른 모습으로 나타납니다.

## 제출물

아래 세 개의 상태 메시지 각각에 대해, 그 메시지가 화면에 그대로 찍히도록
하는 신호 파일을 하나씩 만들어 **`solution/` 디렉터리 안에** 제출합니다.

| 제출 파일 경로 | 화면에 찍혀야 할 메시지 |
|---|---|
| `solution/signal_1.txt` | `connected` |
| `solution/signal_2.txt` | `disk space low` |
| `solution/signal_3.txt` | `Error 404 Host Down Retry 3` |

- 세 파일은 모두 `solution/` 디렉터리 하위에 두어야 합니다.
- 대소문자, 숫자, 공백을 모두 정확히 구분합니다.
- 위 표의 백틱(`` ` ``)은 메시지에 포함되지 않습니다. 그 안의 글자만
  대상입니다.
- 각 메시지의 글자 하나하나가 신호 파일의 한 줄에 대응합니다.

## 보장 사항

- **글자 식별성**: 글자의 생김새는 실행할 때마다 달라지지만, 같은 글자는
  언제나 같은 글자로 알아볼 수 있도록 그려집니다.
- 평가 대상은 여러분이 제출한 신호 파일이며, 그 파일이 지정된 메시지를
  정확히 재현하는 정도에 따라 점수가 매겨집니다. 채점은 화면 출력이 아니라
  제출한 신호 파일의 내용을 기준으로 하므로, 글자의 생김새가 매번 달라지는
  것은 채점에 영향을 주지 않습니다.

## 도구 사용

문제를 푸는 과정에서 **어떤 도구든 자유롭게 사용할 수 있습니다.**
다만 평가되는 것은 최종 제출물과 그 정확도이며, 주어진 도구와 자료를
얼마나 잘 활용했는지가 결과에 드러나게 됩니다.

## 제공 파일

```
glyphd                상태 표시 모듈 실행 파일
example_signal.txt    작동하는 예시 신호 파일
README.md             이 문서 (복원 대상 메시지 포함)
```

## 환경 / 실행

- Linux (x86-64) 터미널 환경에서 실행합니다.
- 실행 파일에는 별도의 설치나 의존성이 필요하지 않습니다.
- 결과는 터미널 화면에 그려지므로, 일반적인 터미널에서 실행하십시오.
- 제출은 `signal_1.txt`, `signal_2.txt`, `signal_3.txt` 세 파일을
  `solution/` 디렉터리에 담아 제출합니다.

## 파일 복구

이 디렉터리는 Git 저장소로 초기화되어 있습니다. 제공된 파일을 실수로 수정하거나
삭제했다면 아래 명령으로 처음 상태로 되돌릴 수 있습니다.

```
git checkout -- <파일명>
```

## 주의 사항

본 문제는 제공된 프로그램을 직접 실행해 보고, 입력에 따른 출력 결과를 관찰하여 동작 방식을 추론해야 합니다.
프로그램 파일을 역공학하거나 내부 구현을 분석하여 문제를 해결하려는 시도는 지양해 주시기 바랍니다.
시험 응시자는 프로그램의 실행 결과를 바탕으로 규칙을 파악하고, 이를 이용해 문제를 해결해야 합니다.
